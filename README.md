# OnlineChat

[![Tests](https://github.com/sanjarbek-ashurboyev/OnlineChat/actions/workflows/tests.yml/badge.svg)](https://github.com/sanjarbek-ashurboyev/OnlineChat/actions/workflows/tests.yml)

Real-time one-to-one chat. Messages arrive instantly over WebSockets, users see who is
online, and unread messages get read receipts. Built with Django Channels and Redis,
with a REST API for chat history.

---

## Features

- **Real-time messaging** over a single WebSocket per user (`/ws/inbox/`). New messages
  are pushed to both participants through a Redis channel layer.
- **JWT on WebSockets.** A custom Channels middleware authenticates the socket with the
  same JWT used by the REST API.
- **Online presence.** Each open connection is tracked in Redis with a 90-second TTL, so
  a crashed client goes offline automatically instead of staying "online" forever.
- **Read receipts.** Marking a chat as read updates the messages and notifies the sender
  in real time.
- **Message limits.** Messages are capped at 4,000 characters on both the WebSocket and
  the REST API.
- **Blocking.** A block between two users stops new messages over both the REST API and
  the WebSocket. (The data model and checks are in place; an endpoint for users to
  create blocks is not built yet.)
- **Phone-number accounts.** Users register and log in with an Uzbek phone number.
  Looking up other users by phone number is rate-limited (20 per hour) to prevent
  scraping.
- **Database integrity.** Constraints guarantee one chat per pair of users and that a
  user can't block themselves.
- **API docs** with Swagger UI generated by drf-spectacular.

## Tech stack

| Layer | Tools |
|---|---|
| Backend | Python, Django, Django REST Framework, SimpleJWT, drf-spectacular |
| Real-time | Django Channels, Daphne (ASGI), channels-redis |
| Data | PostgreSQL, Redis (channel layer, presence, cache) |
| Frontend | Plain JavaScript single page served by Django |
| Infrastructure | Docker Compose for PostgreSQL and Redis |

## API overview

| Endpoint | Description |
|---|---|
| `POST /api/v1/auth/register/` | Create an account |
| `POST /api/v1/auth/login/` · `/auth/token/refresh/` | Get and refresh JWT tokens |
| `GET/PATCH /api/v1/auth/profile/` | Your profile and avatar |
| `GET /api/v1/users/lookup/?phone_number=` | Find a user by phone number |
| `GET/POST /api/v1/chats/` | List your chats or start a new one |
| `GET/POST /api/v1/chats/<id>/messages/` | Message history (paginated) or send a message |
| `POST /api/v1/chats/<id>/read/` | Mark a chat as read |
| `WS /ws/inbox/?token=<access token>` | Live messages, read receipts and presence |

Full interactive docs: `/api/schema/swagger-ui/`

## Running locally

Requirements: Python 3.12+ and Docker.

```bash
git clone https://github.com/sanjarbek-ashurboyev/OnlineChat.git
cd OnlineChat
cp .env.example .env              # then set your own passwords
docker compose up -d              # PostgreSQL + Redis

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py runserver   # Daphne serves HTTP and WebSockets
```

Open http://127.0.0.1:8000/ in two browsers, register two users, and chat between them.

## Tests

48 tests cover registration, login and the phone-number lookup (including its rate limit
and blocking), the chat and message REST API, and the WebSocket itself. The WebSocket tests
connect through the full ASGI stack (origin check, JWT middleware, router, consumer) and
check that messages reach both participants and nobody else, that outsiders, blocked users
and oversized messages are refused, read receipts, and online presence across several tabs.

They use SQLite, an in-memory channel layer and an in-memory stand-in for the presence
store, so no PostgreSQL or Redis is needed:

```bash
make test
```
